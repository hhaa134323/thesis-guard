# 破局条件两层 Schema 设计说明（v0.1）

| 项 | 值 |
|----|----|
| 版本 | v0.1 草稿 |
| 日期 | 2026-07-31 |

## 1. 为什么两层

### Layer 1 — 关键假设的镜像条件（mirror）

- **来源**：从用户陈述的关键假设**自动生成候选**。
- **例**：假设「服务收入持续高增」→ 镜像条件「服务收入同比转负」。
- **价值**：抓住「thesis 本身成立所依赖的具体前提被打破」，是个性化、与该笔持仓逻辑强绑定的风险。
- **「无法确定」交互**：用户说不清破什么时 → 菜单给出假设的镜像候选，选一次即填「假设 + 镜像」两槽。

### Layer 2 — 通用红线默认包（redline）

- **来源**：系统默认下发的通用治理类风险，阈值可判定、用户可调。
- **默认三条**：大额罚单 / 高管突变 / 财报重述。
- **价值**：抓住用户容易忘但普遍致命的风险；不依赖具体 thesis。
- **可调**：用户可调阈值、可关停某条。

### 两层分工

| 层 | 防什么 | 个性化 | 兜底 |
|----|--------|--------|------|
| Layer 1 mirror | 「我的逻辑错了」 | 强（与该 thesis 绑定） | — |
| Layer 2 redline | 「公司出大事我没注意」 | 弱（通用） | 是 |

合起来才完整：前者抓个性化破局，后者兜底通用治理风险。

## 2. 可判定性（judgeability）硬约束

- 任一层任一条条件，必须能映射到一个「可被一手公开披露击中的事件」。
- 不可判定者：录入阶段追问改造；仍不可判定 → 降级为「人工自查项」。
- 每条条件附一个**真实历史事件示例**，帮用户理解「击中时长什么样」。

## 3. 状态机

每条条件每日核对后落一个状态：

- `untriggered` 未触发
- `watch` 需关注（证据部分相关 / 拒判 / 无法判定）
- `triggered` 已触发（附一手证据）
- `triggered` **必须用户动作收尾**：确认破了 / 标记误报 / 忽略 → 沉淀为 eval 标注。

## 4. 价格图形型 → 人工自查项

- 用户原始理由若依赖价格图形（跌破均线、头肩顶等），系统不接行情（v1 无价格类警报）。
- 记为 `manual_check_items`，`cadence=monthly`，每月提醒用户自查。
- 不进入自动核对 loop（不违反「不接行情」约束）。

## 5. schema 落点

见 `docs/thesis-card-schema.md` 的 `broken_conditions` 字段：

- `layer`: `mirror | redline`
- `mirror`: `source_assumption_id` 指向其镜像的假设。
- `redline`: `template`（large_fine / exec_change / restatement）+ `threshold`。
- 共有：`text` / `judgeable` / `historical_example` / `status` / `evidence`。
