## 1. 一句话定位

用户用自然对话把**模糊的投资想法变成可检验的破局条件**；之后由系统核对 Agent 在数据更新时（财报、公告、监管进展、新闻）用一手公开披露核对可核对的条件，无法自动核对的显式列为人工交接项并给出下次自查日期；跨时间持续记住每条条件的状态与变化，免去用户自行搜索整理。主要产出不是「该买／该卖」，而是「我替你查过了，没事」——其中「查过了」必须可核验，见 §4-A。判断权永远归用户。

## 2. 产品价值形态（一切设计的判据）

**让「什么都不做」变得可信。**

- 用户价值 = 消除行动焦虑 + 省去信息搜集成本。
- 推论：用户唯一会质疑的是「你凭什么说没事」→ **系统可信度 > 系统覆盖面**。可信度取决于用户知道系统查了什么、没查什么，不取决于查得多全。

## 3. 核心需求（按优先级）

1. **把模糊的投资想法变成可检验的破局条件**（录入 / 澄清）。
2. **免去自行搜索整理，且能跨时间持续记住**（追踪 / 记忆）。

非核心（不做或后置）：交易决策辅助、行为纠偏、社交、组合优化。

## 4. 设计约束

**A. 覆盖率必须显式呈现，不允许静默跳过。**
- 简报中每只票列出：本次检查覆盖 n/m 条破局条件，逐条标注**已核对**（附数值 + 数据来源 + 数据日期）或**未核对**（附原因：需人工判断 / 无数据源 / 第三方数据）+ 下次人工自查日期。
- `manual_items` 定位从「系统缺陷」改为**「明确交接给用户的清单」**——用户知道哪些得自己看，不是系统漏了。

**B. 时长约束（是上限，不是留存目标）。**
- 日常查看 ≤ 3 分钟；新增标的录入 ≤ 15 分钟。
- 若日常耗时上升，视为**产品退化**而非粘性提升。

**C. 形态锚定简报，不发明新交互。**
- 用户已有稳定的「看简报」习惯，新版是**更好的简报**。
- 任何要求用户改变行为习惯的设计，需先论证收益 > 迁移成本。

## 5. 核心场景

### S1 对话式录入
- 用户自然对话说明持有理由。
- AI 必须追问（可判定性引导），把破局条件编译成结构化 thesis 卡。
- 经用户复述确认后入库。
- 用户表示「无法确定」时给候选菜单（假设与其镜像条件），选一次填两槽；每条附真实历史事件示例。
- 用户原始理由若是价格图形型 → 记为「人工自查项」，每月提醒自查。

### S2 条件核对（数据更新时触发）
- 核对 Agent 在数据更新时（财报 / 公告 / 监管进展 / 新闻）用 SEC EDGAR（按申报方类型路由，外国发行人以 6-K 为主）+ 公开新闻标题 RSS 核对**可核对的**破局条件；无法自动核对的显式列为人工交接项（见 S5 / §4-A）。
- 输出状态机卡片：未触发 / 需关注 / 已触发，附证据与一手链接。
- **覆盖率显式**（约束 A）：每条标注已核对（附数值 + 来源 + 日期）或未核对（附原因）+ 下次自查日期。

### S3 触达（简报形态，约束 C）
- 命中条件当天单独发邮件。
- 未命中合并进简报一行带过，**不单独打扰**。
- 无事那行不许空（约束 A）：「已检查 N 只 / 0 触发 / 最近一个裁判日：X 的 Y 月 Z 日」——让用户确认系统活着。

### S4 收尾（用户动作）
- 「已触发」必须用户动作收尾：确认破了 / 标记误报 / 忽略。
- 误报与确认数据自动沉淀为 eval 标注。

### S5 人工自查项（明确交接，非系统缺陷）
- 价格图形型 / ETF 类（v1 无数据源）等无法自动核对的破条件 → 每月提醒自查。
- 简报里**显式列为「需你自查」清单**（约束 A），不静默跳过。

## 6. 非目标（Non-goals）

- 不给买卖建议、不推荐标的、不做仓位建议。
- 不预测涨跌、不输出目标价、不承诺收益。
- 不接入券商账户、不读取真实持仓、不代客操作。
- v1 不含价格类警报。
- v1 锁美股，不做 A 股 / 港股。
- 不做注册系统（5 人 beta 预置账号）。
- 不上应用商店、不提交小程序审核。
- 不做付费功能（LLM 成本作者自担）。
- 不写入用户 Notion 工作区。
- **不做「决策入口」功能**（我想买 X → 给判决）——见 §7 撤回理由。

## 7. 撤回：决策入口功能（我想买 X → 给判决）

> 留痕，防止以后重新捡起来。

**不做。** 理由：
1. 用户实际使用模式是**被动接收简报**，不会主动发起询问。该功能需要用户主动开口，与真实行为不符。
2. 「守纪律」经作者确认**不是待解决痛点，而是现有方案已达成的成果**——作者原话：「自从有了这个，基本都是 follow 上面动手，半年内无破纪律行为」。
3. 主动咨询场景仅出现在「新增标的」时，该场景**已被录入 Agent 覆盖**，不需要独立功能。

## 9. 技术与分发约束

- 桌面 localhost 单页（对话+确认卡）：FastAPI 托管前端静态产物（React+Vite+shadcn 构建，2026-08-02 修订）+ .bat 启动（用户不碰 shell）；见 §11 沿革 + `docs/frontend-design-v1.md`。不上应用商店、不做小程序。
- 部署中立：代码随时能原样上公网——配置一律走环境变量（不写死 localhost/127.0.0.1、不留本机绝对路径），启动脚本与主程序解耦，目录按「一个命令可容器化」组织。本轮仍只跑本地、不加登录层（本地自用），不做云部署。
- 前端栈：React + Vite + shadcn/ui（2026-08-02 修订，**作废**此前「单 HTML+原生 JS 无构建链」约束）；构建产物静态文件由 FastAPI 托管，部署中立不变。组件库管皮肤，交互结构以 `docs/frontend-design-v1.md` 为准。
- 数据源仅限 SEC EDGAR 官方接口 + 公开新闻标题 RSS（见 `docs/data-sources.md`）。**ETF/基金类 v1 不支持自动核对**（无指数/基金/价格数据）→ 全 manual，显式交接（约束 A）。
- 按申报方类型路由披露表单：外国发行人（20-F/6-K 申报方）以 6-K 为主渠道，不得沿用美国本土公司的「6-K 降级」规则。
- 不使用任何需要商业授权的行情数据；v1 不含价格类警报。
- v1 锁美股，不做 A 股/港股。
- 触达仅邮件。
- 后端从简：预置账号、仅邮件触达、单数据库。

## 11. 沿革（Pivot 记录）

本项目有意偏离历史 spec `assets/notion/spec_public_v1_20260610.md`（参考后归档）：

- **自部署 → 托管 PWA → 桌面 CLI → 桌面 localhost 单页**（形态演化）：原 spec 自部署 → 2026-06-10 改托管 PWA（移动端优先）→ 2026-08-02 改桌面 CLI → 同日再改桌面 localhost 单页（对话+确认卡，FastAPI + 单 HTML + .bat 启动，用户不碰 shell）。砍 PWA 理由：① 交互本质是对话（说+拍板）+推送（有事叫我）+检查面（确认卡+eval 报告），GUI 只是皮肤，砍 PWA 是设计决策不是缺口；② 建设者侧核心交付是 harness + 双层 eval + error analysis 闭环，PWA 从来不是卖点；③ 每天 1 分钟体检哲学是「不要刷、等它叫你」，与 PWA 打开刷形态根本矛盾。CLI→localhost 页理由（同日第二次）：① 目标用户非技术投资者，shell 门槛与受众错配（与 R7「Notion 使用者不多」同一逻辑）；② 当前形态服务叙事与 demo，页面对面试官更直观；③ 界面传统、交互 AI，追问/复述/确认的录入引擎不变只换承载层；④ 录入 8 屏原本就是图形化对话流程，回归原设计非新增。
- **四判决 → 只核对不判决**：原方案含「四判决」（多维度投资判决），本产品只核对条件是否被事件击中，判断权归用户。
- **决策入口 → 撤回**（2026-08-02）：原考虑「我想买 X → 给判决」入口，撤回（理由 §7）——用户被动接收简报、守纪律已是成果、新增标的已被录入 Agent 覆盖。
- **W2 优先级重排**（2026-08-02）：原「接更多数据源」→ 新「覆盖率透明化 → 观察区分流 → 记忆/跨期追踪 → 补数据源（按覆盖率增量排序）」。理由：核心价值是可信的不作为，可信度取决于用户知道系统查了什么/没查什么，不取决于查得多全。
- **decision_influence 首个闭环案例**（2026-08-02 记）：CGNX 系统建立前持仓，系统上线后依其输出分批减仓至清仓——定性基线（非自报），证明 decision_influence 非空。

## 12. 里程碑（4 周，每周约 10 小时）

| 周 | 目标 | 验收 |
|----|------|------|
| W1 | 对话录入跑通：录入 Agent + eval（客观一致率 + 主观盲评） | 客观一致率 ≥85%（逐字段，clean 组）+ 主观接受率 ≥85% |
| W2 | **覆盖率透明化 + 观察区分流 + 记忆/跨期追踪**（重排，非"接更多数据源"） | 每条破局条件可核对性标注 + 简报呈现；观察区按距破线远近排序；本季 vs 上季距离变化 |
| W3 | 招募 5 个外部用户（熟人 + 社区混合；招募前补命名和一页纸 pitch），加埋点，观察首次录入卡点 | 专项观察：破条件自发 vs 菜单挑选比例 |
| W4 | 基于反馈做一次有取舍的迭代 | KILL 判据体检：7 天打开 <5 天，或没有一次影响过用户决策 → 停掉不养老 |

W2 重排细节（按优先级）：
1. **覆盖率透明化**：每条破局条件的可核对性标注 + 简报呈现（约束 A）。
2. **观察区分流**：按距破线远近排序，只展示逼近的标的。
3. **记忆/跨期追踪**：本季距离 vs 上季距离，变化即内容。
4. **补数据源**：之后才接，且按「能提高覆盖率多少」排序（非市占率 / 监管 / 非美竞品 / 第三方铺开）。

> **副产品（2026-08-02）**：`entry_anchor.history` 结构落地（thesis-card-schema §5）后，「当前价距破线的距离」及其季度间变化可直接计算，**不需新增数据源**。这是上面 #2（观察区分流）+ #3（记忆/跨期追踪）的底层数据——两者优先级相应**上调**。

> **2026-08-02 W2 重排（开工指令）**：本轮 W2 = 录入 loop（P0）→ 核对 agent loop → 输出层 → W2 eval 改造（测收敛后接受率/平均澄清轮数/收敛失败率），带断点 ①（录入 loop 演示）②（W2 报告）。上表 W2 行的覆盖率透明化/观察区分流/记忆追踪顺延至断点 ② 之后。见 §14。
